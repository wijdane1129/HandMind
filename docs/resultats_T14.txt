HandMind - Résultats du test T14 (cohérence avatar)
Semaine 4 - Étudiant B (Avatar & Interface)
Date : 16/11/2026
=====================================================

OBJECTIF
Vérifier que l'avatar réagit correctement aux messages reçus par WebSocket.
Critère du cahier des charges : 100 messages connus envoyés ->
100 % des animations correspondent à la classe reçue.

PROCÉDURE
- Serveur de test : python ws_server.py --cadence 2 --nombre 100
  (100 messages numérotés de 0 à 99, 2 messages par seconde, soit environ 50 s)
- Client : Godot 4.7.2 (WebSocketClient.gd + main.gd), lancé avant le serveur,
  un seul client connecté
- Séquence : les 5 classes en rotation (repos, main_gauche, main_droite,
  deux_mains, deux_pieds)
- Pour chaque message, Godot joue l'animation correspondante, puis vérifie
  que l'animation en cours est bien celle attendue

CORRESPONDANCE CLASSE -> ANIMATION
repos        -> repos
main_gauche  -> main_gauche
main_droite  -> main_droite
deux_mains   -> deux_bras
deux_pieds   -> accroupi

RÉSULTAT
T14 : 100 reçus, 100 animations correctes, 0 erreurs, 0 doublons -> RÉUSSI
Séquence reçue : numéros 0 à 99 complets, dans l'ordre

LIMITES
- Test en local (même machine), donc pas de latence réseau réelle
- Confiance fixe à 0,87 et prédiction toujours égale à la vraie classe :
  le cas "prédiction fausse" (texte rouge) n'est pas couvert par ce test
- La latence (test T13) est mesurée séparément

HISTORIQUE DES ESSAIS (corrections apportées)
- Essai 1 : 69 messages reçus (n°30 à n°98). Invalide : un autre client était
  encore connecté, donc Godot est arrivé après le message n°30 ; le dernier
  message a aussi été perdu à la fermeture du serveur.
- Corrections : pause de 1 s avant la fermeture du serveur, lecture des
  derniers paquets même après la fermeture, compteurs remis à zéro à chaque
  connexion, verdict exigeant la séquence 0 à 99 complète.
- Essai final : RÉUSSI (résultat ci-dessus)
